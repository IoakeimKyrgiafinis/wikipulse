# observability/: metrics, dashboards and alerts as code (spec 09a)

| Path | What it is |
|------|------------|
| `dashboards/*.json` | Grafana dashboards: pipeline health, detection, LLM usage, model health. Generated by `scripts/dashboards.py`; don't edit by hand |
| `alerts/wikipulse.rules.yaml` | Prometheus alert rules: no events, consumer and detector lag, service down, extraction failures, drift |
| `alerts/wikipulse.rules.test.yaml` | Unit tests for the rules (`promtool test rules`) |
| `kube-prometheus-stack.yaml` | Values for the community chart that installs Prometheus and Grafana, kept lean |

The metrics themselves are defined in `wikipulse/metrics/catalog.py`; every service serves
them on `METRICS_PORT` (`/metrics`). Terraform installs everything into the kind cluster
(`infra/cluster/monitoring.tf`, see `infra/README.md`).

```
uv run python scripts/dashboards.py            # regenerate the dashboards after a change
uv run python scripts/dashboards.py --check    # are the JSON files current?
docker run --rm -v "${PWD}/observability/alerts:/rules" -w /rules --entrypoint promtool quay.io/prometheus/prometheus:v3.12.0 test rules wikipulse.rules.test.yaml
```

Explanation, decisions and results: `docs/learning/09a-metrics-dashboards.md`.
